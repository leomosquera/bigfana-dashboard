# BigFana Domain Model

## Purpose

This document defines the conceptual domain model of BigFana.

The goal is to describe business entities, responsibilities, and relationships before defining database structures.

This document intentionally avoids:

- database tables
- column definitions
- implementation details
- API contracts

Those concerns belong to future documentation.

This document represents the business language of the platform.

---

# Domain Overview

BigFana is a sports engagement, loyalty, and monetization platform.

The platform connects:

- sports organizations
- fans
- sponsors
- competitions
- content
- campaigns
- loyalty programs

while generating behavioral intelligence through EEP.

---

# Sport

Represents a sport category.

Examples:

```txt
Football
Basketball
Rugby
Volleyball
Tennis
Esports
Motorsports
```

Responsibilities:

- categorization
- navigation
- segmentation
- reporting

Relationships:

```txt
Sport
    ↓
Competition
```

---

# Competition

Represents a league, tournament, championship, or organized ecosystem.

Examples:

```txt
Liga Profesional Argentina
La Liga
Premier League
Liga MX
NBA
Kings League
```

Responsibilities:

- competition structure
- standings
- schedules
- fixtures
- rankings

Relationships:

```txt
Sport
    ↓
Competition
    ↓
Organization
```

A competition may be:

```txt
Integrated
Managed
```

as defined in ADR-005.

---

# Organization

Represents a sports entity.

Examples:

```txt
River Plate
Boca Juniors
Real Madrid
Argentina National Team
Chicago Bulls
Porcinos FC
```

Responsibilities:

- community management
- loyalty ownership
- benefits
- rewards
- campaigns
- sponsor relationships
- fan engagement

Relationships:

```txt
Competition
    ↓
Organization
    ↓
Fan Relationship
```

---

# Fan

Represents a platform-level sports fan.

A fan exists independently of any specific organization.

Responsibilities:

- participation
- engagement
- loyalty activity
- content interaction
- competition interaction

Relationships:

```txt
Fan
    ↓
Primary Organization

Fan
    ↓
Followed Organizations

Fan
    ↓
Followed Competitions

Fan
    ↓
Sports Interests
```

Defined by:

- ADR-001
- ADR-002

---

# Membership

Represents the relationship between a fan and an organization.

Examples:

```txt
Primary Membership

Followed Membership

Competition Membership
```

Responsibilities:

- define relationship type
- support loyalty ownership
- support audience generation

---

# Loyalty Program

Represents the loyalty system owned by an organization.

Responsibilities:

- points
- levels
- benefits
- rewards
- engagement incentives

Ownership:

```txt
Organization
    ↓
Loyalty Program
```

Loyalty is organization-owned.

---

# Points Ledger

Represents all point transactions generated by fan activity.

Examples:

```txt
Trivia Participation
Match Prediction
Reward Redemption
Sponsor Activation
```

Responsibilities:

- traceability
- auditing
- loyalty balance calculation

---

Examples:

```txt
Organization
```

# Audience

Represents a targetable group of fans.

Examples:

```txt
Highly Engaged Fans

Fans Interested in European Football

Fans Following Multiple Sports
```

Ownership:

```txt
EEP
```

BigFana consumes audiences.

EEP generates audiences.

---

Examples:

```txt
Casual Fans
International Fans

```

Ownership:

```txt
EEP
```

EEP generates segments.

# Future Domain Expansion

The model is intentionally designed to support future entities such as:

- seasons
- divisions
- tournaments
- fantasy competitions
- marketplace
- digital collectibles
- memberships
- subscriptions
- fan identity profiles

without requiring fundamental redesign.
