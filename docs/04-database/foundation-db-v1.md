# BigFana Foundation Database v1

## Purpose

This document defines the target evolution path of the BigFana database.

The goal is not to redesign the platform from scratch.

The goal is to evolve the current database toward the architecture defined by:

- ADRs
- Domain Model
- Logical Model

while preserving existing functionality whenever possible.

---

# Foundation Principles

Foundation Database v1 must support:

- multi-tenant architecture
- multi-sport architecture
- multi-competition architecture
- global fan model
- organization-owned loyalty
- EEP integration
- sponsor activations
- future platform expansion

The migration strategy should prioritize incremental evolution over disruptive redesign.

---

# Migration Strategy

The database evolution will occur in phases.

Each phase must be independently deployable.

Each phase must preserve compatibility with existing production functionality.

---

# Phase 1 — Global Fan Model

## Objective

Migrate from organization-owned fans to platform-level fans.

Current Model:

```txt
Organization
    ↓
Fan
```

Target Model:

```txt
Fan
    ↓
FanOrganization
    ↓
Organization
```

Defined by:

- ADR-001
- ADR-002

---

## New Entities

```txt
fan_organizations
```

---

## Responsibilities

Support:

- primary organization
- followed organizations
- future competition representation

---

## Expected Result

Fans become platform-level identities.

Organizations own relationships rather than fan records.

---

# Success Criteria

Foundation Database v1 is considered complete when:

- Global Fan Model exists
- Sports hierarchy exists
- Competition hierarchy exists
- Loyalty lifecycle exists
- Sponsor ecosystem exists
- Content platform exists
- Match center exists
- EEP audiences are supported

without requiring architectural redesign.
