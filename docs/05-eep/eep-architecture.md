# BigFana EEP Architecture

## Purpose

This document defines the relationship between BigFana and EEP.

The goal is to clearly define:

- ownership boundaries
- responsibilities
- synchronization flows
- event architecture
- audience architecture
- campaign architecture

EEP is the intelligence layer of the BigFana ecosystem.

BigFana is the engagement and experience layer.

---

# Architectural Principle

BigFana and EEP are complementary systems.

Neither system should duplicate the responsibilities of the other.

BigFana generates behavior.

EEP transforms behavior into intelligence.

BigFana consumes intelligence.

---

# System Responsibilities

## BigFana Responsibilities

BigFana owns:

```txt
Organizations

Fans

Campaigns

Content

Benefits

Rewards

Points

Levels

Matches

Competitions

Sponsors

Notifications

Fan Experiences
```

BigFana is responsible for:

```txt
Engagement

Participation

Gamification

Loyalty

Community Building

Monetization
```

---

## EEP Responsibilities

EEP owns:

```txt
Audience Generation

Behavioral Analysis

Segmentation

Scoring

Recommendations

Profile Enrichment

Predictive Intelligence
```

EEP is responsible for:

```txt
Intelligence

Audience Discovery

Behavior Analysis

Sponsor Targeting
```

---

# Core Principle

BigFana sends:

```txt
Behavior
```

EEP returns:

```txt
Intelligence
```

---

# Event Architecture

Every relevant fan action generates an event.

Examples:

```txt
Fan Registration

Login

Campaign Participation

Trivia Answer

Survey Response

Prediction

Reward Redemption

Benefit Usage

Content View

Match Interaction

Sponsor Interaction
```

---

# Event Flow

```txt
Fan Action
    ↓
BigFana
    ↓
Fan Event
    ↓
Integration Job
    ↓
EEP
```

---

# Event Ownership

Events are generated by BigFana.

Events are stored by BigFana.

Events are synchronized to EEP.

EEP may enrich the event data but does not own the source event.

---

```txt
VIP
```

# Segment Flow

```txt
Behavior
    ↓

    ↓
```

---

# Campaign Architecture

Campaign creation belongs to BigFana.

Examples:

```txt
Trivia

Survey

Poll

Prediction

Sponsor Activation

Reward Campaign
```

EEP does not create campaigns.

EEP helps define audiences for campaigns.

---

# Campaign Targeting Flow

```txt
BigFana
    ↓
Request Audience
    ↓
EEP
    ↓
Audience
    ↓
BigFana Campaign
```

---

# Sponsor Architecture

Sponsors interact with audiences generated by EEP.

Example:

```txt
Sponsor
    ↓
Target Audience
    ↓
Campaign
    ↓
Fan Interaction
```

---

# Fan Profile Enrichment

EEP may enrich fan profiles with:

```txt
Affinity Scores

Behavior Scores

Interest Categories

Audience Memberships

Engagement Scores
```

BigFana consumes these attributes.

EEP owns the calculations.

---

# Synchronization Principles

Synchronization must always be:

```txt
Asynchronous

Retryable

Idempotent

Non-Blocking
```

---

# Availability Principle

BigFana must continue operating if EEP becomes unavailable.

Example:

```txt
EEP Offline

BigFana Continues

Events Queued

Synchronization Retried Later
```

Fan experience must never depend on EEP availability.

---

Future EEP responsibilities may include:

```txt
Sponsor Matching

Audience Lookalikes

Behavior Forecasting
```

These features belong to EEP.

---

# Future BigFana Features

Future BigFana responsibilities may include:

```txt
Community Experiences

Cross Organization Campaigns

Competition Experiences

Loyalty Networks

Fan Missions

Global Challenges
```

These features belong to BigFana.

---

# Database Direction

BigFana stores:

```txt
fan_events

integration_jobs
```

EEP stores:

```txt
audiences

segments

scores

behavioral models
```

BigFana consumes audience and segment information.

---

# Success Criteria

The integration is successful when:

- BigFana generates all fan behavior
- EEP receives all relevant events
- EEP generates meaningful audiences
- BigFana can target campaigns using EEP intelligence
- BigFana remains operational if EEP becomes unavailable
